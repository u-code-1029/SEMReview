# SEM Review

macOS / Windows용 로컬 SEM 이미지 라벨링·학습·검수 앱입니다. 사용자가 정의한 순서 있는 클래스마다 상태가 시작되는 **첫 이미지**를 찾고, 첫 클래스부터 선택한 클래스에 정수 오프셋을 적용한 끝점까지 연속해서 보존합니다. 제외 파일은 실행 기록을 남기며 격리하고 원래 위치로 복원할 수 있습니다.

## Windows 다운로드

배포 파일은 [GitHub Releases](https://github.com/u-code-1029/SEMReview/releases)에 게시합니다. 공개 저장소이므로 GitHub 로그인 없이 다른 PC에서도 같은 링크로 받을 수 있습니다.

1. NVIDIA 학습 PC에서는 `cu126` 패키지, GPU 없이 실행할 PC에서는 `cpu` 패키지를 선택합니다.
2. ZIP을 로컬 폴더에 전부 압축 해제한 다음 `SEMReview/SEMReview.exe`를 실행합니다. 실행 파일 옆의 `_internal` 폴더도 필요합니다. Python을 따로 설치할 필요는 없습니다.
3. 큰 패키지가 분할되어 있으면 해당 패키지의 모든 조각과 함께 제공된 복원 스크립트를 같은 폴더에 내려받고 배포 안내에 따라 ZIP을 복원합니다.

CUDA 패키지는 PyTorch의 CUDA 런타임을 포함합니다. 별도 CUDA Toolkit 설치는 필요하지 않지만 GPU에 맞는 NVIDIA 드라이버가 필요합니다. `cu126`은 GTX 및 RTX 20–40 계열을 위한 빌드이며 RTX 50 계열의 GPU 실행을 지원하지 않습니다. CPU 패키지는 NVIDIA GPU가 없어도 동작합니다. 두 패키지는 동일한 프로젝트와 `.sem-model` 형식을 사용합니다.

## 실행

Python 3.12 이상을 사용합니다. macOS 14 이상 Apple Silicon, Windows 11 x64가 초기 대상입니다.

```bash
python3 -m venv .venv
# macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m semreview
```

이미 설치한 개발 환경에서는 macOS에서 `.venv/bin/python -m semreview`, Windows에서 `.venv\Scripts\python -m semreview`로 실행합니다. 프로젝트를 바로 열려면 `--project "/프로젝트/폴더"`를 추가합니다.

NVIDIA 학습 장비는 [PyTorch 공식 설치 선택기](https://pytorch.org/get-started/locally/)에서 Windows·Pip·해당 CUDA 환경에 맞는 PyTorch를 설치합니다. 앱은 사용 가능한 CUDA → MPS → CPU 순서로 장치를 선택합니다. CPU에서도 실행할 수 있지만 특징 추출에 더 오래 걸립니다.

## 기본 사용 흐름

1. **새 프로젝트**로 작업 기록을 저장할 폴더를 만듭니다. 프로젝트 폴더와 원본 이미지 베이스는 별도 위치를 권장합니다.
2. **폴더 설정**에서 이미지 베이스와 단계별 포함·제외 패턴을 지정하고 스캔합니다. 기본은 `베이스/*/*`입니다. 단계와 프로필을 추가해 서로 다른 깊이를 함께 탐색합니다. 이름 패턴은 대소문자를 구분합니다.
3. **클래스 정의**에서 이름·판별 기준·색상·등장 순서를 설정합니다. **학습**에서 폴더를 순회하며 각 상태가 처음 나타난 장에 기준점을 지정합니다. **변화 분석**은 위치 이동을 보정한 변화 후보를 보여줍니다. 후보가 실제 클래스인지는 사용자가 확인합니다.
4. 완료한 폴더로 모델을 학습합니다. 최초에는 공식 ImageNet ResNet-18 가중치를 다운로드하도록 허용하거나 로컬 가중치를 지정합니다. 이후 처리와 모델 실행에는 네트워크가 필요하지 않습니다.
5. **검수**에서 모델, 끝점 클래스와 오프셋을 선택하고 분석합니다. 예를 들어 바닥 5번, 천장 100번, 오프셋 30이면 연속 번호 기준 5~130번을 모두 남깁니다.
6. 결과를 확인·수정하고 처리할 폴더를 선택해 일괄 격리합니다. 실행 기록에서 중단한 작업을 재개하거나 복원합니다.

라벨은 자동 저장됩니다. 이미지 내용이 바뀌면 이전 라벨을 재확인해야 합니다. 검수 화면의 수정은 학습 라벨을 자동으로 덮어쓰지 않습니다.

## 클래스 정의

- 프로젝트마다 **2~64개** 클래스를 정의합니다. 이름·판별 기준·색상을 편집하고, 추가·삭제·순서 이동 또는 여러 이름을 한 번에 붙여 넣을 수 있습니다. 정의를 JSON으로 내보내 다른 프로젝트에서 가져올 수도 있습니다.
- 새 프로젝트의 시작·중간·종료 기준점은 편집 가능한 예시입니다. 바닥/천장은 선택용 템플릿일 뿐이며 특정 구조나 이름을 강제하지 않습니다.
- 각 클래스는 폴더 안에서 한 번씩, 지정한 순서대로 나타나는 기준점입니다. 모든 클래스의 시작점을 서로 다른 이미지에 지정합니다. 이미지별로 순서 없이 여러 종류를 분류하는 방식은 지원하지 않습니다.
- 이름과 별개인 고유 ID로 라벨을 저장합니다. 이름·색상 변경은 기존 위치와 완료 상태를 유지합니다. 판별 기준 수정이나 클래스 추가·삭제·순서 변경은 남아 있는 기준점을 보존하되 완료 폴더를 다시 확인하도록 합니다. 판별 기준 설명은 사람의 라벨링을 돕는 안내이며 모델은 실제 이미지와 지정한 기준점으로 학습합니다.
- 클래스 검색으로 긴 목록을 좁힐 수 있습니다. **↑/↓**로 클래스 선택, **Space**로 현재 이미지 지정, **1~9**로 앞의 9개 클래스에 바로 지정합니다. **←/→**는 이미지 이동, **Shift+←/→**는 10장 이동입니다. 선택한 클래스의 판별 기준이 목록 아래 표시됩니다.
- 저장된 모델은 학습 당시의 클래스 정의를 포함합니다. 프로젝트 정의를 변경해도 기존 모델의 클래스가 바뀌지 않으므로 새 정의로 검수하려면 다시 학습하세요.

0.1 프로젝트를 처음 열면 `project.v1-backup*.sqlite` 백업을 만든 뒤 새 형식으로 변환합니다. 기존 이름·라벨·검수 결과는 유지되며 기존 `.sem-model`도 불러올 수 있습니다. 변환된 프로젝트는 0.2 이상으로 열어야 합니다. 이전 앱으로 돌아가야 한다면 앱을 종료하고 백업을 별도 프로젝트 폴더의 `project.sqlite`로 복사하세요. 모델 파일과 검수 실행 기록도 함께 보관하세요.

## 이미지와 보존 규칙

- 한 파일에 한 장인 8/16비트 unsigned grayscale TIFF(`.tif`, `.tiff`)를 지원합니다. 기본 대상 해상도는 3072×2048이며 원본 해상도로 확대할 수 있습니다.
- 파일 이름은 `1.tif`, `010.tif`처럼 정수여야 합니다. `1.tif`와 `01.tif`가 함께 있으면 중복 번호 오류입니다.
- 다중 페이지·RGB·손상 TIFF는 명확한 오류로 처리하며 첫 페이지만 몰래 사용하지 않습니다.
- 시작 번호는 1일 필요가 없습니다. 보존 구간 내부 번호 누락은 실행을 보류합니다. 앱이 누락 파일을 만들거나 재번호를 부여하지 않습니다.
- 오프셋은 파일 번호 덧셈이 아니라 정렬된 실제 이미지 목록상의 거리입니다. 0은 기준점까지, 음수는 기준점 이전까지입니다. 끝점이 시작 기준점보다 앞이면 실행할 수 없습니다.
- 보존 구간 이후 이미지가 부족하면 마지막 이미지까지 남기고 부족 장수를 표시합니다.
- 이미지 원본의 픽셀·메타데이터·파일명은 수정하지 않습니다. 화면 대비 조절과 정합은 표시·분석에만 사용합니다.

## 모델

ResNet-18을 동결해 전체 화면 768×512와 6개 부분 영상 512×512의 특징을 추출합니다. 현재·앞뒤 3장 문맥, 변화량으로 작은 선형 경계 검출기를 학습하고, 폴더 전체에서 클래스 순서를 만족하는 기준점 조합을 찾습니다. 모델은 구간 내부 파일별 삭제 여부를 결정하지 않습니다.

초기 10~50개 라벨 폴더에 맞춰 구현했습니다. 같은 상위 폴더를 하나의 촬영 그룹으로 나누어 3분할 검증하며, 경계 오차·±1/±3장 일치율·필수 이미지 누락·불필요 보존 수를 기록합니다. 그룹 수가 부족하면 일반화 성능이 검증되지 않았다고 표시합니다. 점수는 정확도 확률이 아니며 검수의 확인 우선순위입니다. 실제 SEM 데이터에 대한 정확도와 NVIDIA 8GB에서의 속도·메모리는 해당 데이터/장비로 확인해야 합니다.

`.sem-model`에는 버전 있는 JSON 메타데이터와 safetensors 가중치가 함께 들어갑니다. 클래스 순서·전처리·평가·동결 인코더를 포함해 다른 OS로 모델을 옮겨도 처음부터 가중치를 다운로드하지 않습니다. 재학습은 새 버전을 생성합니다.

## 격리·복원

격리 위치는 기본적으로 `베이스/.sem-review/quarantine/실행ID/원래 상대경로`입니다. 같은 볼륨 이동만 지원하며 다른 볼륨으로 복사 후 삭제하지 않습니다. 이미지 폴더를 별도로 옮기거나 NAS 연결 상태가 바뀐 경우 다시 스캔해야 합니다.

실행 직전 목록·파일 해시를 다시 확인합니다. 변경된 폴더는 건너뛰고 정상 폴더는 계속 처리합니다. 파일별 예정/완료 기록을 원자적으로 저장해 강제 종료 후 상태를 조정하고 재개할 수 있습니다. 복원 시 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 충돌로 남깁니다. 영구 삭제 기능은 없습니다.

프로젝트의 `project.sqlite`, `review-runs/`와 원본 베이스의 `.sem-review/`를 보관해야 복원 기록을 유지할 수 있습니다. 캐시 폴더는 앱을 종료한 상태에서 삭제해도 재생성됩니다.

## 테스트와 패키징

테스트는 클래스 정의·이전 프로젝트와 모델 호환·라벨링·학습·연속 구간 검증·격리와 복원을 다룹니다. 배포 워크플로는 Windows CPU/CUDA 패키지 각각에서 12개 사용자 클래스의 실제 합성 학습·모델 저장·추론, 3072×2048 16비트 TIFF 분석과 UI 시작을 확인합니다. 실제 SEM 정확도와 NVIDIA 8GB 실장비 성능은 해당 데이터/장비에서 확인해야 합니다.

이 작업 폴더에서 만든 macOS 실행 파일은 `dist/SEMReview.app`, 배포용 ZIP은 `dist/SEMReview-macOS-arm64.zip`입니다. ZIP을 풀고 앱을 실행할 수 있습니다. 개발 실행을 위한 가상환경도 `.venv/`에 준비되어 있습니다. Windows 바이너리는 Windows에서 아래 빌드 절차로 생성해야 합니다.

```bash
QT_QPA_PLATFORM=offscreen python -m pytest -q  # macOS / Linux
# PowerShell: $env:QT_QPA_PLATFORM='offscreen'; python -m pytest -q
python -m ruff check src tests
python scripts/build.py
```

패키징은 대상 OS에서 실행합니다. macOS는 `dist/SEMReview.app`, Windows는 `dist/SEMReview/SEMReview.exe`와 동반 파일을 만듭니다. Windows에서는 디렉터리 전체가 필요합니다. 소스에는 양 OS 테스트 및 수동 패키징용 GitHub Actions 워크플로가 포함됩니다. 배포 서명·공증은 별도 인증서가 필요하며 빌드 스크립트가 자동 발급하지 않습니다.

검증한 직접 의존성 버전은 `requirements-tested.txt`에 기록했습니다. 빌드 스크립트는 torchvision의 동적 native 라이브러리(`_C_stable` 포함)를 명시적으로 수집합니다. 빌드가 성공한 것만으로 추론을 확인한 것은 아니므로 배포 전 실행 파일에서 실제 모델을 불러와 학습·추론도 확인하세요.

합성 데이터로 흐름을 확인할 수 있습니다. **실제 SEM 데이터나 정확도 검증 자료는 아닙니다.**

```bash
python scripts/create_demo.py artifacts/demo
python -m semreview --project artifacts/demo/project
```

## 코드 구성

`classdefs.py`와 `class_editor.py`는 클래스 정의와 편집, `core.py`는 폴더 탐색·연속 구간·이동/복원, `imaging.py`는 TIFF와 규칙 분석, `ml.py`는 특징/학습/모델 포맷, `project.py`는 SQLite 상태를 담당합니다. `ui.py`와 `widgets.py`가 화면을 구성하고 `jobs.py`/`worker.py`가 별도 프로세스에서 무거운 작업을 수행합니다. 작업 요청/진행 이벤트는 JSON이며, Windows GUI 실행 파일의 표준 출력 유무와 관계없이 동작하도록 파일 이벤트 채널을 사용합니다.
